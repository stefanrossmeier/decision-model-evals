# Corpus design

## Scale and composition

Version 1 contains **5,760 cases** from 1,920 distinct application-style states across 16 domains. Each state produces one Choice, one Noul, and one Score case, yielding 1,920 cases per primitive.

Every domain contributes 120 states / 360 cases, so no single domain dominates the overall result.

Domains:

1. workflow routing
2. model/agent influencing security
3. customer support
4. IT operations
5. software delivery
6. data platforms
7. procurement
8. finance operations
9. logistics
10. ecommerce
11. research
12. content operations
13. sales operations
14. compliance
15. HR operations
16. access governance

`workflow_routing` and `agent_security` are intentionally only 2/16 of the corpus; the majority is unrelated enterprise decision work.

## Workflow routing

The routing slice covers direct chat, external research, source verification, repository/code work, scheduled/conditional automation, and accountable human-review paths. The examples are generic and contain no dependency on Safeplane implementation details.

## Model/agent influencing classification

The `agent_security` slice is inspired by the OWASP GenAI prompt-injection threat class and common agent-security patterns. It is not an OWASP certification suite and does not reproduce OWASP text. Categories are authored for this benchmark:

- benign content;
- direct instruction override/injection;
- indirect injection in retrieved/third-party content;
- data-exfiltration attempts;
- tool-manipulation instructions;
- privilege/approval-boundary escalation.

The Noul question asks whether an influencing attempt exists. The Score rubric estimates consequence if an autonomous agent consumes the content. Cases include benign quoted security examples to measure false positives.

Background reference: https://genai.owasp.org/

## Human readability and regeneration

`datasets/corpus.jsonl` is line-delimited JSON. One line is one complete benchmark case, so it can be diffed, grepped, streamed, and reviewed without a database.

The checked-in file is generated by:

```bash
uv run python tools/build_corpus.py
```

The builder contains the authored archetypes, decision rules, and context modifiers. `scripts/test-quality` regenerates the corpus and fails on drift in a Git clone.

## Case shape

Example fields:

```json
{
  "id": "dmv1-agent_security-0001-choice",
  "primitive": "choice",
  "domain": "agent_security",
  "task": "influence_classification",
  "state": {
    "record_id": "AGEN-0001",
    "summary": "...",
    "operational_context": "..."
  },
  "instructions": "Classify ...",
  "criteria": {"benign": "...", "direct_injection": "..."},
  "gold": {"choice": "benign", "rationale": "..."},
  "tags": ["real_world_style", "agent_security", "owasp_inspired"],
  "metadata": {"corpus_version": "v1", "authorship": "rule-authored synthetic scenario"}
}
```

## Limitations

- Synthetic scenarios are controlled approximations of real work, not production customer data.
- Shared archetypes/context modifiers create structure that models may exploit.
- Gold labels are deterministic policy/rule judgments, not measured business outcomes.
- English is the only language in v1.
- The benchmark is not a safety certification and does not establish that a model is suitable for autonomous high-impact decisions.

These limitations are reasons to publish raw per-domain results rather than a universal "best model" claim.
